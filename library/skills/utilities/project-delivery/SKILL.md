# Delivery criteria

Use this optional skill when a request lacks an observable definition of completion.
For each key user journey, identify its entry point, successful outcome, relevant failure
behavior and evidence that would establish it works. Separate product decisions from assumptions.

Keep durable scope in the project brief, visual decisions in the design contract, and the
current state, checks, blockers and next step in a short handoff note. Use ordinary Markdown
when these documents do not exist. Native host planning and sessions manage execution.

A delivery handoff distinguishes implemented behavior from configured dependencies and
unverified integrations. State whether evidence came from a local fixture, mock or real service;
do not let a successful build imply a working integration or deployment.
